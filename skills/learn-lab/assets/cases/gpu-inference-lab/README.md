# GPU 推理实验室 · 交互课件

把「大模型在线推理时显存、带宽和 GPU 各自在做什么」做成可操作的单页课件，
回答一串连起来的问题：权重放在哪 → 为什么带宽成为瓶颈 → 这些单位到底在量什么 →
量化省了什么 → batch 如何翻转瓶颈 → 投机解码何时加速何时拖慢。

- `index.html` —— 单文件交互课件，无构建、无依赖，直接浏览器打开

## 阅读模型：渐进式深入

页面不平铺讲义，按「懂的时候不看、不懂的时候再查」组织，共四层：

| 层级 | 形态 | 作用 |
|---|---|---|
| L0 默认可见 | 交互教具 + 读数 | 不读任何文字也能玩 |
| L1 折叠标题 | 问句 + 一句话结论 | 扫一眼就知道要不要展开 |
| L2 展开正文 | 小标题分段 + 要点列表 | 真正的推导，分段不堆砌 |
| L3 悬浮/抽屉 | 术语 tooltip、参数 `?`、答疑面板 | 随时插入，不打断主线 |

具体实现：

- **15 个折叠块** —— 概念解释默认收起，摘要行已给出结论（`<b>` 高亮关键词），
  只有 2 个默认展开（模块 03 的词性表、模块 05 的屋顶图解）
- **10 个悬浮提示** —— 3 个正文术语（虚线下划线）+ 7 个参数 `?` 按钮，
  统一 tooltip 组件，含「定义 + 参照数值」两段；空间不足时自动翻到下方
- **滑块即时说明** —— 每个滑块下方一行动态文字，随值变化改写
  （如 batch 从「算力闲置 99%，验证几乎免费」变成「算力已饱和，验证付满 K 倍」）
- **答疑抽屉** —— 右下角常驻入口，15 条按 4 类组织的问答 + 关键词搜索 +
  「去对应模块」跳转；底部可一键复制**带当前参数的提问模板**，拿去问任意 AI

## 模块 06 的逐轮回放

原来只有一排彩色 token，看不出含义。现改为自解释的四态回放：

| 状态 | 样式 | 含义 |
|---|---|---|
| 猜对 | 绿色实线 | 草稿和主模型答案一致 → 保留 |
| 猜错 | 红色删除线 | 草稿吐出错词 → 丢弃并截断 |
| 没验到 | 灰色虚线 | 前面已截断，这些连验证机会都没有 |
| 补正 | 蓝色，前有 `→` | 验证这一步本身必定产出的 1 个正确 token |

关键设计：维护两套词表 `SD_TOK`（正确答案）和 `SD_BAD`（似是而非的错词），
猜错时显示错词、补正时显示正确词，**让「猜错 → 补正」的对比肉眼可见**。
随机序列固定（`SD_RND`），拖动滑块时不会整片乱跳。

每个 token 都带 `title`，悬浮说明它的具体遭遇。
下方一句话旁白自动改写，直接回答「所以呢」。

## 计算模型

基准全部按 RTX 4090 官方规格：带宽 1008 GB/s、FP16 算力 165 TFLOPS（Tensor Core dense，
未采用带稀疏的 330）、Roofline 拐点 = 165000/1008 ≈ 164 FLOP/Byte。

- 单步搬运耗时 = 模型体积 ÷ 带宽；计算耗时 = 2×参数量 ÷ 算力；实际取两者较大值
- 算术强度近似取 batch size（单请求解码时 ≈ 1 FLOP/Byte）
- 投机解码期望接受长度 `E = (1-α^(K+1))/(1-α)`，含验证必得的 1 个 token
- 单轮成本 `= 1 + (K-1)·f + 0.04K`，其中 `f = min(1, AI/164)` 为算力饱和度；
  f→0 时并行验证近乎免费，f→1 时验证付满 K 倍

## 模块 08 的换卡对照

| 卡 | 显存 | 带宽 | FP16 | 拐点 |
|---|---|---|---|---|
| RTX 4090 | 24 GB | 1008 GB/s | 165 TFLOPS | 164 |
| RTX 3090 | 24 GB | 936 GB/s | 71 TFLOPS | 76 |
| A100 80GB | 80 GB | 2039 GB/s | 312 TFLOPS | 153 |
| H100 SXM | 80 GB | 3350 GB/s | 990 TFLOPS | 296 |

关键反直觉点：H100 带宽是 4090 的 3.3 倍但算力是 6 倍，所以拐点反而更高，
数据中心卡在单用户解码下浪费的算力比例比消费卡更夸张。

## 实测结论（页面内可复现）

| 场景 | K | α | batch | 加速比 |
|---|---|---|---|---|
| 本地 · 代码补全 | 4 | 75% | 1 | 2.59× |
| 本地 · 创意写作 | 4 | 30% | 1 | 1.21× |
| 云端 · 大 batch | 4 | 75% | 512 | 0.73×（变慢） |

## 一处自我更正

讨论过程中我先用过「大 batch 下传送带已经满载」的比喻，这个说法不准确，
页面模块 05 末尾已显式纠正：两种场景下带宽利用率都接近 100%，
真正变化的是算力利用率（0.6% → 100%）。投机解码的本质是「多算换少搬」，
所以它只在算力有富余时免费，算力饱和后变成纯开销。

## 数据可信度分级

页面模块 08 对每个数字标注了三类来源：

- **官方规格** —— 显存容量、带宽、FP16 算力、L2 缓存，可自行查证
- **推导值** —— Roofline 拐点，由上面两项相除得到，非独立数据
- **量级近似** —— 主机内存带宽、NVMe 带宽、片内带宽，标注了 `~` 前缀

模型侧：`2 × 参数量 = 单 token FLOP` 是业界标准估算，忽略 attention KV、LayerNorm、
softmax 开销，短上下文误差在 10% 内，长上下文不适用。

### 过程中实际修掉的问题

1. **折叠标题三列错位** —— `grid-row` 写了但没写 `grid-column`，问句被挤到标签右侧，
   补齐显式列定位后恢复
2. **列表项被 grid 拆行** —— `.pts li` / `.ad-a li` 用 `display:grid` 时，
   句中的 `<strong>` 会被当成独立网格项占一行（实测单行高度 55px）；
   改为 `position:relative` + 绝对定位的 `::before` 后恢复为 22px
3. **补正 token 和被丢弃的 token 同词** —— 原逻辑两者都取自同一词表，
   看不出「猜错了被纠正」；新增 `SD_BAD` 错词表后对比才成立
4. **窄屏宽表格撑破页面**（上一轮）—— 横向溢出 52px，改为表格自身滚动后归零
5. **「L1 / 寄存器延迟」标签写错**（上一轮）—— 单位是带宽不是延迟，已更正
6. **插入新模块时误删了 `<section id="m5">` 开标签**（回流轮）—— 编辑的 old_string
   匹配到了 `</section>` + 下一个 `<section>` 的边界，导致投机解码模块被并进 Roofline。
   浏览器实测报 `mods=7` / `navOk=false` 才发现。
   教训：在模块边界插入内容时，old_string 不要跨越 `</section>` 标签。
7. **`1008 GB/s` 被显示成「1 TB/s」**（回流轮）—— 换算阈值写成 `>=1000` 导致精度丢失，
   改成 `>=2000` 才换算。这类四舍五入会让读者对不上官方规格。
