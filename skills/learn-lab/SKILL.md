# 学习实验室

产出一个无依赖的单 HTML 文件：**打开就能动手试，试完就懂**。

## 这个 skill 管什么、不管什么

**管**：信息怎么组织、教具怎么自解释、数字从哪来、怎么验收。
这些是教学设计问题，不随模型能力变化。

**不管**：用什么配色、什么布局、怎么写 CSS、用不用 canvas。
这些你自己判断，按主题选最合适的形态。

读完本文档你应该知道「一份好课件长什么样」，而不是「照哪个模板填空」。

## 课件交付后：追问要记得更新课件

**这是最容易漏的一步。** 用户追问时，默认反应是在聊天里答一遍就完 ——
但课件已经存在了，答案应该补进去。聊天记录会沉掉，课件会被反复打开。

所以：**同主题的追问 = 更新课件 + 回复给摘要**，而不是只回复。

补在哪里按问题性质定。有一条值得单独说：
如果追问暴露的是「这件事有多种情况」（换个口径/参数结论就变），
**做一个能切换的教具，而不是写一段文字** —— 文字只能讲一种情况，教具能让读者穷举。

补完照常跑验收。追加内容最容易破坏模块编号、术语引用和提问模板，
细节见 [迭代模式](references/iteration.md)。

## 判断主题适不适合

至少命中两条：

| 特征 | 例子 |
|---|---|
| 有定量关系，能算出数 | 带宽 × 时间 = 字节数 |
| 有可调参数，值变了结论跟着变 | batch 越过拐点，瓶颈从带宽换成算力 |
| 有反直觉结论 | H100 带宽更高，浪费的算力比例反而更大 |
| 有常见误解要纠正 | 「把模型搬进 GPU」不是一次性塞进缓存 |
| 有多个量纲容易混 | FLOP / FLOPS / FLOP·B⁻¹ |

**不适合**：纯定性的概念辨析、没有参数可调的叙事、只有一条结论的事实查询。
这类直接写清楚就行，强行做交互只增加噪音。

## 核心：四层信息架构

这是整个 skill 最重要的一条，也是最容易做错的一条。

**默认平铺是错的。** 一页从上到下铺满讲义，读者必须顺序读完才能找到自己的疑问。
正确做法是分层，让「懂的人不用看、不懂的人查得到」。

| 层 | 内容 | 服务谁 | 硬性要求 |
|---|---|---|---|
| **L0** | 交互教具 + 实时读数 | 想直接上手的人 | **不读任何文字也能操作** |
| **L1** | 折叠标题：问句 + 一句话结论 | 快速扫读的人 | **收起态就能看到结论** |
| **L2** | 展开后的推导 | 要搞懂的人 | **分段，禁止大段堆砌** |
| **L3** | 术语悬浮、参数说明、答疑入口 | 卡在某个词上的人 | **不打断主线阅读** |

### L1 的关键：摘要必须给结论

```
▸ 为什么每个 token 都要把整个模型重搬一遍？
  因为生成是自回归的：不知道第 N 个，就算不出第 N+1 个。      [展开推导]
```

**判定标准：只读摘要行，能不能答出标题的问题？** 能，这个摘要就合格。

- 标题用**问句**，不是陈述式小标题。问句才能让读者判断「这是不是我的疑问」
- 摘要里高亮 1-2 个关键词
- 标签标明内容类型（展开推导 / 纠正误解 / 易错点 / 勘误 / 对照表）
- **默认全部收起**，只有「不先看就无法理解教具」的才默认展开，一页不超过 2 个

反面例子：摘要写「点开看详细说明」——等于没写。

### L2 的关键：分段

一个折叠体里有多个论点，就用小标题切开，一个标题管一件事。
并列关系用列表，步骤关系用编号列表。

**禁止**把三件事塞进一个段落。这是第一版最容易犯的错。

### L3 的关键：随处可查

三个插入点，缺一个读者就会卡住：

- **术语** —— 正文里的生词可悬浮查看定义
- **参数** —— 滑块旁有说明入口，且**滑块下方有一行随值改写的动态提示**
- **答疑** —— 常驻入口，按「读者真实卡点」而非知识树组织

动态提示是最廉价的自解释手段。静态括号（「Batch size（同时处理的请求数）」）
信息量远低于「同时处理 **1** 个请求 · 算力闲置 **99%**，验证几乎免费」。

详见 [信息架构](references/architecture.md)。

## 核心：教具必须自解释

一个教具至少包含三件东西：

```
可调参数 ──→ 实时读数（数值是多少）
         └──→ 结论（这些数值意味着什么）
```

**第三项最常被漏掉。** 只给数字不给解读，读者的反应是「我看懂数字在变，但不知道这意味着什么」。

结论要**随参数改写**，包括状态名、配色、正文。不是一段静态文字。

### 自解释四问

做完一个教具，按这四条自查，任一条答不出就是没做完：

1. **不读页面任何正文，能不能操作？**（标签、图例、单位是否齐全）
2. **拖动后，读数变化的含义是否自明？**（每个读数有没有参照值或算式）
3. **有没有一句话告诉我「所以呢」？**（结论是否随参数改写）
4. **看不懂某个元素时，能不能查？**（关键元素有没有说明入口）

读数卡的参照值最容易省。「算术强度 1.0」本身没有意义，
「1.0 ／ 拐点 = 164」才让读者知道这个 1.0 是大还是小。

### 形态自由

层级条、流程动画、坐标图、沙盘、逐轮回放、树、时序图、地图——
按主题选，也可以发明新的。**唯一约束是过上面四问**。

但有一类值得单独说：**多状态离散过程**（有成功/失败/丢弃等分支）。
这类不要只给一排彩色方块，要展开成逐轮回放，每个元素可查、每轮有汇总、
示例数据能体现差异。这是真实迭代中改动最大的一处。

详见 [教具设计](references/instruments.md)。

## 核心：数字必须可追溯

没有真实参数的课件是空壳。读者无法验算，只能选择信或不信。

额外好处：**反直觉的结论往往来自真实数据的不均衡**。
比如 H100 带宽是 4090 的 3.3 倍但算力是 6 倍，导致拐点更高、浪费更多——
这种结论编不出来。

三级可信度，每个数字必须归类并在页面上标明：

| 级别 | 含义 | 要求 |
|---|---|---|
| **官方规格** | 厂商/标准文档明确标注 | 给出可自行验算的方式 |
| **推导值** | 由官方值算出，非独立数据 | **写出算式** |
| **量级近似** | 实测有差异，取通用值 | 标 `~` |

还要注意：说明用的是哪个口径（dense/sparse、理论/实测）、
两套进制并存时统一一种并说明、简化模型要声明边界。

详见 [数据与可信度](references/data-sourcing.md)。

## 工作流程

### 1. 先定基准，再写内容

挑一个**最容易验证**的具体对象（某张显卡、某个协议版本、某个真实价目表），
查清官方规格，做成一张参数表。后面所有交互从它派生。

**所有派生值实时计算，不硬编码结论。** 这样换基准时只改一处，
也避免不同对象之间的结论不自洽。

额外做一组可切换的对比基准（如换几张卡），让读者看到「换一个会怎样」——
这是把单点知识变成可迁移理解最有效的手段。

### 2. 设计模块与教具

每个模块回答一个问题，模块之间形成因果链。在导语和结论里显式串起来，
最后做一个「全景速查」把链条压缩成一页。

每个教具过自解释四问。

### 3. 实现

单文件 HTML，无构建无依赖。视觉和技术选型自由，但要满足：

- **语义标记** —— 关键结构加 `data-ll-*` 属性（见下），便于自动校验
- **移动端可用** —— 窄屏无横向溢出
- **无控制台报错**

#### 语义契约

为了能自动校验教学设计属性，关键元素加这些属性。
**这不限制你怎么写样式或结构**，只是让校验脚本能识别语义：

```html
<!-- 折叠块：标题 + 摘要 -->
<details data-ll="fold">
  <summary>
    <span data-ll="fold-q">问句标题？</span>
    <span data-ll="fold-tldr">一句话结论</span>
  </summary>
  <div data-ll="fold-body"> ... </div>
</details>

<!-- 读数：值 + 参照 -->
<div data-ll="read">
  <span data-ll="read-k">指标名</span>
  <span data-ll="read-v">1.0</span>
  <span data-ll="read-ref">拐点 = 164</span>   <!-- 必需 -->
</div>

<!-- 参数：滑块 + 动态提示 + 说明入口 -->
<div data-ll="ctl">
  <input type="range" ...>
  <span data-ll="ctl-hint">随值改写的说明</span>  <!-- 必需 -->
  <button data-ll="explain" data-term="xxx">?</button>
</div>

<!-- 结论：随参数改写 -->
<div data-ll="verdict"> ... </div>

<!-- 术语 -->
<span data-ll="term" data-term="xxx">术语</span>

<!-- 数据来源 -->
<span data-ll="src" data-src-kind="spec|calc|approx">官方规格</span>

<!-- 模块 -->
<section data-ll="module"> ... </section>
```

术语说明的数据结构也约定一下，便于校验引用完整性：

```js
window.LL_TERMS = {
  xxx: { title:'...', body:'...', ref:'...' }   // ref 可选
};
```

### 4. 验收

```sh
python3 "<skill-dir>/scripts/serve.py" "/absolute/path/output-dir"
```

然后用浏览器工具跑教学设计校验：

```sh
myflicker-browser evaluate --tab-id <tabId> \
  --expression-file "<skill-dir>/scripts/pedagogy-check.js" --timeout-ms 60000
```

它检查的是**教学设计属性**（摘要有没有给结论、读数有没有参照、
参数有没有动态提示、术语引用是否完整、默认展开是否过多），
不是 CSS 细节。

**然后必须截图肉眼看。** 脚本只能验证结构性属性，
「这个教具到底讲清楚了没有」只能人看。

详见 [验收](references/validation.md)。

### 5. 交付

- `index.html` —— 单文件
- `README.md` —— 必须含**基准参数来源**、**计算模型**、**验证记录**三节。
  验证记录写实际修掉了什么，不要写「一切正常」。

## 文字风格

这是给一个具体的人解释一件具体的事，不是写科普文。

1. **结论先行。** 摘要行、结论卡、答疑条目都是先给答案再给推导。
2. **类比要在量纲上成立。** 发现类比不准确要**显式纠正**，不要悄悄换说法。
3. **承认不确定。** 量级近似标 `~`；简化模型说清「定性可靠、数值不等于实测」。
4. **保留勘误。** 早先说错的地方留一个「勘误」折叠块写清楚。
   这比偷偷改掉更有价值——读者会记住这个点。
5. 避免 AI 套话、成串排比、「不是……而是……」。中文用中文标点，代码单位保留原文。

## 第一版就该做对的事

这些是真实迭代中被用户指出才改的，列在这里是为了**第一版就不犯**：

1. **不要平铺。** 概念解释默认折叠，摘要给结论。
2. **教具要自解释。** 过四问，特别是「所以呢」那一问。
3. **参数要有动态提示。** 不要只在括号里写静态定义。
4. **要有答疑兜底。** 常驻入口 + 可导出带当前参数的提问模板
   （单文件无法联网，这是最接近「直接对话」的形式）。
5. **数字要标来源。** 三级可信度。
6. **首屏要说明怎么读这页。** 四层架构对第一次打开的人不是自明的。
