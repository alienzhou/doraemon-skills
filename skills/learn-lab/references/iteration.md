# 迭代模式

已有课件的改进诉求对照。先读现有文件和 README 的「验证记录」，只改相关部分。

这份清单的来源是真实反馈。**列在这里的目的是第一版就不犯**，而不是等被指出再改。

迭代分两类，处理方式不同：

| 类型 | 触发 | 特征 |
|---|---|---|
| **改进型** | 用户直接指出课件的问题 | 「太平铺了」「教具看不懂」—— 改已有内容 |
| **追问型** | 用户追问主题内容 | 「拐点是推算的吗？」—— 补新内容，见下 |

## 追问型：记得更新课件

用户追问主题内容时（不是指出课件问题），**答案要补进课件**，回复只给摘要。
容易漏的一步，所以单独提一句。

先确认课件在哪：看上下文有没有提过路径，或翻一下工作区的产物目录。
不确定就直接问一句，不要为此拖延回答。

补在哪里按问题性质定：

| 问题性质 | 补在 |
|---|---|
| 暴露概念理解缺口 | 对应模块新增折叠块 |
| 问某个词是什么 | 术语字典 + 正文标记 |
| 「为什么是这个数」 | 数据来源模块补标注 |
| **有多种情况/口径要对比** | **新增教具** |
| 常见困惑但不值得占正文 | 答疑面板加一条 |
| 发现原有内容有误导 | 改原内容 + 加「勘误」块 |

**第四行值得单独说。** 如果追问暴露的是「这件事有多种情况」，
做一个能切换的教具比写一段文字好 —— 文字只能讲一种情况，教具能让读者穷举。

真实案例：用户问「拐点是硬件参数还是推算的」，表面是个是非题，
实际暴露的是「同一张卡有多个拐点」，所以补的是
`4 种算力口径 × 3 层存储` 的矩阵教具。

回复格式：一句话结论 + 补在哪里 + 文件链接。不要在聊天里复述课件内容。

## 诉求 → 改法

### 「内容太平铺了，页面太长」

最常见的第一版问题。按 [信息架构](architecture.md) 改：

1. 找出所有「小标题 + 多段正文」的组合
2. 每组改成折叠块
3. **标题改成问句**，写一句话结论作为摘要
4. 展开后用小标题重新分段，并列内容改列表
5. 默认全部收起，只留必须先看的 1-2 个

**一次改完所有模块。** 混用两种形态比统一平铺更乱。

### 「行文是一大段，读起来负担重」

和上一条经常同时出现。不只是折叠的问题，展开后的内容也要重排：

- 多个论点用小标题切开，一个标题管一件事
- 并列关系抽成列表
- 加粗控制在每段 1-3 个

### 「教具看不懂 / 不知道在表达什么」

按 [教具设计](instruments.md) 的自解释四问排查，通常缺：

| 缺什么 | 症状 |
|---|---|
| 图例 | 不知道颜色/状态代表什么 |
| 参照值 | 看到数字但不知道大还是小 |
| 结论 | 「我看懂数字在变，但不知道这意味着什么」 |
| 逐元素说明 | 想知道某个具体元素的遭遇但无处可查 |

如果是**多状态离散过程**（有成功/失败/丢弃分支），考虑整体改成逐轮回放。

### 「参数太多，不知道每个是什么意思」

三件事叠加，缺一个都不够：

1. 参数旁的说明入口（可悬浮）
2. 滑块下方的**动态提示**（随值改写）
3. 有场景名的预设按钮

不要把说明写进静态括号里，信息量太低。

### 「想要能直接提问」

加答疑面板。单文件无法联网，所以是「预置问答 + 提问模板导出」：

1. 按真实卡点分 3-5 类，每类 3-4 条
2. 问题用读者原话
3. 每条带「去对应模块」跳转
4. 底部一键复制**带当前参数状态**的提问模板

### 「数据是编的还是真的」

补数据来源交代。按 [数据与可信度](data-sourcing.md)：

1. 基准对象逐项参数表，三级标注 + 验算方式
2. 换基准对比的交互（派生值实时算）
3. 「为什么选这个基准」
4. 公式来源和简化边界

如果原来有数字确实是编的，**换成真实值并重算所有派生结论**，不要只补标签。

### 「新增一个模块」

容易漏的三处：

1. 导航要加项，且**后续所有模块编号都要改**
2. 正文里交叉引用的「模块 0X」要同步改
3. README 的模块表要更新

跑 `pedagogy-check.js` 会检查导航与模块的一致性。

## 必须保留的东西

- **已确认的「勘误」块** —— 这是诚实记录，不要因为重构删掉
- **README 的验证记录** —— 追加新发现，不要覆盖旧的
- **基准对象** —— 除非用户要求，不要换，否则所有数字都要重算
- **用户认可过的交互** —— 即使你觉得有更好的形态，也应新增而非替换，或先问

## 迭代后的验证

**全量重跑**，不只测改动部分。重构共享组件会影响全页，插入新内容会破坏跨模块一致性。

追加内容最容易破坏四处，前三项 `pedagogy-check.js` 能抓，最后一项只能人工核对：

| 破坏点 | 症状 |
|---|---|
| 模块结构被吃掉 | 模块数变少、导航锚点失效 |
| 模块编号错位 | 导航编号与正文对不上 |
| 术语引用悬空 | 新增 `data-term` 忘了加字典条目 |
| **提问模板过期** | 新增参数没同步进导出文本 —— **脚本抓不到** |

最后一项要特别注意：模板的作用是让读者带完整上下文去问 AI，
**少一个参数，导出的上下文就是残缺的**。每次新增可调参数都要回头改它。

另外一条编辑上的坑：**在模块末尾追加内容时，`old_string` 不要跨越 `</section>`**。
跨越了会把下一个模块的开标签一起吃掉，两个模块被合并 ——
症状是模块数少 1、导航失效，但页面看着「好像正常」，因为内容都还在，只是结构塌了。

其他回归重点：窄屏溢出、术语浮层定位、状态翻转时结论是否仍正确改写。

最后在 README 的验证记录里追加一节，写清这轮补了什么、因为什么问题。
这样下次打开能看出课件是怎么长成现在这样的，同一个问题也不会被补两遍。

## 不要做的事

- **不要为了用新组件而改已经好用的部分。** 判断标准是「读者会不会更容易懂」，
  不是「代码会不会更统一」。
- **不要在一轮里同时改结构和内容。** 先把结构改对、验证通过，再改文字。
