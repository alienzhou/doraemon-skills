# 信息架构

四层的详细写法与判定标准。这份文档讲**怎么判断分层做对了**，不讲用什么 CSS。

## 为什么必须分层

平铺讲义的问题不是「不好看」，是**强迫所有读者走同一条路径**：

- 已经懂的人被迫滚过大段解释才能找到教具
- 不懂的人不知道哪段解释对应自己的疑问
- 卡在某个术语上的人只能离开页面去搜

分层的目标是让**同一份内容服务不同状态的读者**，各取所需。

## L0：默认可见

只有两类东西该默认可见：**交互教具**和**实时读数**。

硬性要求：**不读任何文字也能操作**。

判定方法：把页面上所有 `<p>` 隐藏掉，教具还能用吗？
- 滑块知道在调什么吗（标签 + 单位）
- 图形的颜色含义清楚吗（图例）
- 读数知道是什么指标吗（指标名）

模块导语（一两句说清「动手做什么、重点看哪」）也属于 L0，但要短。

## L1：折叠标题

### 结构

收起态必须同时呈现三件事：

```
▸ 问句标题？
  一句话结论，关键词高亮。             [内容类型标签]
```

### 判定标准

**只读摘要行，能不能答出标题的问题？**

| 标题 | 摘要 | 判定 |
|---|---|---|
| 为什么权重只能住 VRAM？ | 点开看详细说明。 | ✗ 等于没写 |
| 为什么权重只能住 VRAM？ | 关于 GPU 存储层级的说明。 | ✗ 只说了话题 |
| 为什么权重只能住 VRAM？ | 因为计算芯片自己的存储只有**几十 MB**，连 1B 模型都装不下。 | ✓ |

### 标题用问句

陈述式标题要求读者先读正文才知道讲什么；问句让读者立刻判断「这是不是我的疑问」。

| 不好 | 好 |
|---|---|
| 关于自回归生成 | 为什么每个 token 都要把整个模型重搬一遍？ |
| 量化的收益 | 量化省的只是显存吗？ |
| MTP 简介 | MTP 和传统投机解码有什么区别？ |

**如果这份课件源于一次真实对话，直接用用户当时的问法。**

### 内容类型标签

让读者判断「这段值不值得展开」：

| 标签 | 用在 |
|---|---|
| 展开推导 | 有算式和表格的完整论证 |
| 纠正误解 | 读者很可能有的错误图景 |
| 易错点 | 容易混淆的命名、单位、符号 |
| 勘误 | 你自己早先说错的地方 |
| 对照表 | 纯查表内容 |
| 答疑 | 回应一个具体提问 |
| 扩展 | 主线之外的延伸 |

### 默认展开的判断

只有满足「不先看就无法理解教具」才默认展开。一页不超过 2 个，否则等于没折叠。

典型该展开的：核心概念的对照表、解释教具坐标轴含义的图解。

## L2：展开后的推导

### 必须分段

多个论点就用小标题切开，一个标题管一件事。

```
一句话原因
  ...
于是一步的收支是这样
  ▸ 支出：搬 32 层权重 ≈ 14 GB
  ▸ 产出：只算出 1 个 token
两条耗时赛跑，慢的那条说话
  [表格]
```

**禁止**把三件事塞进一个段落。这是第一版最容易犯的错，
也是用户反馈里明确提到的「整个行文是一大段，读起来负担有点重」。

### 并列用列表，步骤用编号

```
并列：▸ int8 —— 基本无损
      ▸ int4 —— 多数任务可接受
      ▸ int2 —— 开始明显掉质量

步骤：1 搬第 1 层权重进片内缓存
      2 算第 1 层，算完立刻丢掉
      3 搬第 2 层 → 算第 2 层 → 丢掉
```

### 重点标注的节制

一段里加粗超过 3 个就失去强调作用。算式、单位、标识符用等宽样式而不是加粗。

## L3：随处可查

三个插入点，缺一个读者就会卡住。

### 术语悬浮

正文里的生词可查定义。说明分三部分：

```
标题（含中英对照）
正文（1-3 句，说清是什么 + 加粗关键定性）
参照（给一个具体数值锚定抽象概念，可选）
```

参照那一行很有用：「显存带宽」是抽象的，「4090：1008 GB/s」是具体的。

定位要有翻转逻辑：**上方放不下就翻到下方**，否则视口顶部的触发点会跑出屏幕。
触屏要支持点击切换，不能只绑 hover。

### 参数说明 + 动态提示

两件事，都要有：

1. **说明入口** —— 滑块标签旁一个可悬浮的入口，解释这个参数是什么
2. **动态提示** —— 滑块下方一行，**随值改写**

动态提示是最廉价的自解释手段：

```
静态（差）：Batch size（同时处理的请求数）
动态（好）：同时处理 1 个请求 · 算力闲置 99%，验证几乎免费
       →   同时处理 512 个请求 · 算力闲置 0%，验证付满 K 倍
```

读者不需要任何额外操作就知道当前值意味着什么。

### 答疑兜底

常驻入口（如右下角悬浮按钮），点开是一个面板。

**按真实卡点组织，不按知识树：**

| 分类名（好） | 分类名（差） |
|---|---|
| 最容易卡住的地方 | 基础概念 |
| 单位与数字 | 术语表 |
| 我该怎么做 | 应用场景 |

分类名要像读者的心理状态，不要像教材目录。「最容易卡住的地方」放第一。

**问题用读者原话：**

| 不好 | 好 |
|---|---|
| 显存带宽的定义 | 带宽不是网络的概念吗？为什么单机 GPU 也有带宽？ |
| 批处理的适用场景 | 开大 batch 对我个人用户有用吗？ |

**必须有「我该怎么做」类问题。** 纯原理问答容易停在「知道了」，
至少一条落到行动：

> **那我本地想提速，应该做什么？**
> 按性价比排序：量化 → 投机解码 → 换带宽更高的卡…
> 最后一条值得强调：选卡时别只看 TFLOPS。

**要能导出提问模板。** 单文件 HTML 无法联网，所以提供一键复制，
把**当前所有参数状态**打包成文本：

```
我在学 XX，当前上下文：
【基准硬件】RTX 4090 · 1008 GB/s · 165 TFLOPS
  Roofline 拐点 ≈ 164 FLOP/Byte
【当前位置】batch = 1 → 带宽瓶颈，算力利用率 0.61%
我的问题是：
```

读者带着完整上下文去问任意 AI，不用重新解释背景。
加了新参数要同步加进模板。

## 导航与首屏

### 导航副标题

除了编号和标题，加一行「这个模块解决什么」：

```
02  一个 token 的旅程
    为什么卡在搬运
```

让读者能直接跳到自己的疑问，而不是顺序读完。

### 首屏必须说明怎么读

四层架构对第一次打开的人不是自明的，要用三四行说清：

> **怎么读这页：** 概念解释默认**折叠**，标题旁已给出结论，懂的直接跳过、不懂再展开。
> 参数旁的 `?` 和带虚线的术语都可以悬浮查看说明。还有疑问就点右下角**「有疑问」**。

同时固定显示**基准对象**（侧栏或首屏），让读者随时知道数字来源。

## 常见误判

| 症状 | 实际问题 |
|---|---|
| 折叠了但页面还是很长 | 默认展开太多，或摘要写得太长 |
| 读者还是顺序读完 | 标题不是问句，无法判断是否该展开 |
| 读者说「看不懂」 | L3 缺失，卡在术语上无处可查 |
| 读者说「不知道在看什么」 | L0 教具缺图例或结论 |
