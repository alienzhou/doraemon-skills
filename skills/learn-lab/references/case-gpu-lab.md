# 案例：GPU 推理实验室

本 skill 的来源。价值在于它**不是一次做对的**——三轮迭代的演进过程就是这个
skill 存在的理由。

源文件：[assets/cases/gpu-inference-lab/](../assets/cases/gpu-inference-lab/)

## 主题与适配判断

大模型在线推理时显存、带宽、GPU 算力各自在做什么。

**为什么适合**：命中四条特征——有定量关系（带宽×时间=字节）、有可调参数（batch size）、
有反直觉结论（H100 浪费比例更大）、有多个易混量纲（FLOP/FLOPS/FLOP·B⁻¹）。

## 三轮迭代

### 第一轮：有交互，但平铺

六个模块，教具做得不错，但所有解释都是「小标题 + 多段正文」平铺。
页面很长，读者必须顺序读完。

### 第二轮：补内容，平铺问题加剧

用户问了三个问题（单位含义、数据来源、Roofline 名字由来），
加了两个模块和一个图解。内容更完整了，但页面更长。

### 第三轮：改信息架构 ← 本 skill 的核心

用户给了三条反馈，原话是：

> 核心问题是缺少渐进式深入的查看和调节，现在全部平铺出来了。
> 为了顾及版面效率、让页面更加高效，应该做到懂的时候不需要看、不懂的时候再去查。

1. 名词解释应该折叠，而且行文是一大段读起来累
2. 教具操作时看不懂（特别是多状态的 token 流）
3. 参数铺得长，应该 hover 查说明，甚至能直接提问

对应改法：

- 15 个折叠块，摘要行给结论，正文分段 + 列表
- token 流改成逐轮回放：四状态 + 逐元素说明 + 自动改写旁白
- 参数加说明入口 + 动态提示，加答疑面板 + 提问模板导出

### 这一轮的教训

**交互做得好不等于课件做得好。**

第一轮的教具单看都不差——层级条、流程动画、Roofline 坐标图都能用。
问题出在信息架构：什么默认可见、什么按需展开、读者卡住时能不能查。

这就是为什么本 skill 把「四层架构」和「自解释四问」放在最前面，
而不是列举教具类型——**前者是第一版就该做对的，后者各主题各不同。**

## 八个模块与教具形态

| # | 模块 | 教具形态 |
|---|---|---|
| 01 | 存储层级 | 层级对比条（log 宽度 + 亮度编码带宽 + 放入对象判定） |
| 02 | 一个 token 的旅程 | 流程动画（可暂停变速 + 双利用率条 + 累计读数） |
| 03 | 单位与量纲 | 双模式计算器（固定两个推出第三个 + 量纲检查） |
| 04 | 量化 | 档位沙盘（容量量规 + 保真度热图） |
| 05 | Roofline | 图解 + 滑块坐标图（临界点显式标注） |
| 06 | 投机解码 | 时间线对比 + 逐轮回放（四状态） |
| 07 | 全景速查 | 因果链 + 概念表（无交互，纯回看） |
| 08 | 数据来源 | 可信度表 + 换基准对比 |

**这个清单是参考不是清单。** 换主题应该重新想形态，不要照着套。

## 数据基准

RTX 4090，三级可信度：

| 级别 | 项 |
|---|---|
| 官方规格 | 24 GB、1008 GB/s（384bit × 21Gbps ÷ 8）、165 TFLOPS（dense，未用虚高的 330） |
| 推导值 | Roofline 拐点 164（= 165e12 ÷ 1008e9） |
| 量级近似 | 主机内存 ~60 GB/s、NVMe ~7 GB/s |

换基准对比：4090 / 3090 / A100 / H100，拐点 164 / 76 / 153 / 296。

**反直觉结论**：H100 带宽是 4090 的 3.3 倍但算力是 6 倍，所以拐点更高，
单用户解码浪费的算力比例（99.7%）比消费卡（99.4%）还夸张。

这个结论编不出来，只有真实数据才有——这就是「数字必须可追溯」的实际收益。

## 迭代中修掉的 bug

全部由浏览器实测 + 截图发现：

| Bug | 类别 |
|---|---|
| 补正元素和被丢弃的元素同词，看不出「纠正」 | **设计逻辑**：示例数据不能体现差异 |
| 「L1/寄存器延迟」标签写错，单位是带宽 | **事实错误**：量纲没核对 |
| 折叠标题三列错位 | 实现细节 |
| 列表项被布局拆行 | 实现细节 |
| 窄屏宽表格撑破页面 | 实现细节 |

前两条有普遍意义，已写进 skill：
- 多状态教具的示例数据必须能体现差异
- 单位和量纲要逐个核对

后三条是具体实现问题，不同技术栈表现不同，不值得固化成规则。

## 自我更正的示范

课件里保留了一个「勘误」折叠块：

> **一处自我更正：「传送带满载」这个比喻是错的**
> 带宽利用率两种场景下都接近 100%，真正变的是算力利用率。

这是讨论过程中我先用错的比喻。**显式留一个勘误块比偷偷改掉更有价值**——
读者会记住这个点，而且知道这份课件经过了修正。

## 可复用与不可复用

**可复用**：四层架构、自解释四问、三级可信度标注、答疑组织方式、验收标准。

**不可复用**：所有具体数字和结论、教具形态清单、视觉实现。
换主题必须重新收集真实参数、重新想教具形态。

这个案例里的 164 拐点、14 GB、2.59× 加速比，对其他主题毫无意义。
