# 制作与交付要点

## 输入与语音

`inspect` 记录 SHA-256、大小、修改时间、流信息和抽帧。更新视频后重新执行；不能只看文件名判断它没变。不要仅凭文件名推断语言、主题或画幅。

优先使用已有的语音工具或本机环境。Apple Silicon 上本机 MLX Whisper 是一种可选实现：先检查缓存中的模型，再决定是否下载；不需要为了渲染图解安装语音模型。也可使用用户提供的可靠逐字稿。

转写需有词级或句级时间。专有名词、口头停顿和末尾静音容易误识别：自动转写只用于定位，与原声和画面核对，尤其不要把静音末尾的模型幻觉当成内容。没有字幕要求时，转写留在工程里，不烧入画面。

## 主线与画面

先写出“整条视频让观众理解什么”，再为段落选形式。例如，职业转型口播中的内部工具只是实践方法的例子，画面应强调完整负责、积累经验和建立信任，不应另起一章讲内部工具的架构。

并列方法可用分支图；阶段可用递进路径；对比可用并排关系；范围扩大可用边界逐步展开。长章节适当变换视角，保持当前章节可识别。不要把所有段落都做成同样的卡片列表，也不必为了“有动画”不停移动文字。

数字、比例和评分若只是示意，应让示意性质明确。没有依据时优先表达相对关系，不编造测量值。

## 人像裁切与画幅

`portrait.crop` 是自动旋转后的原视频上的归一化 `[x, y, width, height]`。先看实际解码帧再裁切，不照搬旧视频的像素坐标。

至少检查头部最高、最低、最偏移的几帧。主体移动较大时需要分段裁切或跟踪，而不是扩大圆窗遮住正文。保持头顶、下巴和眼镜在可视区域。非正方形 crop 会先等比填满圆窗，再中心裁成正方形。

人像常驻与人像大小是两件事。默认小窗全程可见，不在转场时一起淡出。先渲染背景转场，最后统一叠加同期人像，避免圆窗闪动或重复交叉淡化。

保留输入横竖方向；1080×1920 只是纵向模板。输入 SAR 不为 1 或音视频起始偏移明显时，先明确规范化方案，避免拉伸或重置有意义的音画偏移。工具会报出具体限制，不能忽略后继续。HDR / 广色域素材也应先明确色彩转换方案。

## 时长、音轨与编码

按输出 fps 和窗口时长计算帧数 `ceil(duration * fps)`，不复用旧片的总帧数、章节时刻、分段常数或预览起止时间。原视频比音频短不足一帧时，可延续末帧覆盖音频结尾；若相差明显，要检查源文件，不能把长时间冻结当作正常。

全片默认复制兼容音轨。样片需要同一 seek 起点的画面和声音，可重编码 AAC；不变速、不额外压缩音量、不添音乐或音效。音轨 hash 一致只证明音频保留，不证明人物同步。

常规 SDR 视频可输出 H.264、yuv420p、faststart。图解从 RGB 转 YUV 时明确 BT.709；仅改 metadata 不等于转换色彩矩阵。叠加时保持人物与背景颜色空间一致。

## 可继续使用的工程

推荐结构可按任务调整：

```text
原视频所在目录/
  口播.mp4
  口播制作工程/
    project.json
    storyboard.json
    render_background.py
    video_tools.py
    outputs/
    work/
    README.md
    requirements-render.txt
```

配置中的输入引用尽量相对配置文件；脚本从自身或配置位置解析路径，不依赖启动终端所在目录。工程 README 记录修改入口、具体命令、视频版本和验证结果。明确这是 Python/FFmpeg 工程，不声称是剪映/PR 时间线工程。

复制工具进项目后，技能本身不再是运行时依赖。保留依赖列表；不打包用户媒体进通用技能，也不要把语音模型、虚拟环境、机器上的绝对路径或一次性转写时间戳带进技能包。

若用户要求迁移已有项目：检查目标是否冲突，保留素材和已交付文件，修复输入引用、入口脚本和环境路径；比较重要输出哈希并实际运行预览。是否保留旧位置符号链接取决于原链接仍需可用与否，不默认复制多套大文件。
