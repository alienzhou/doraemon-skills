# 错误处理

任何脚本报错先读本文，再按 stdout 最后一行 JSON 的 `error` 查表，不随意绕过检查、不改用其他技能代码、不杀未知进程。有限命令退出 0 且最后一行 `ok:true` 才算成功；服务器 `running` 仅表示启动，仍需 `/health` 验证身份。

| error | 对应动作 |
|---|---|
| `NODE_NOT_FOUND` | shell 找不到 node 时停止，提示安装 Node.js 22+；不自动安装系统服务。 |
| `INVALID_ARGUMENT` | 展示 msg，按规范修正参数；标题保持用户原意，安全引用路径与文本。 |
| `OUTPUT_EXISTS` | 原目录不变；选择新输出目录，不覆盖、清空或重命名已有用户目录。 |
| `FILE_NOT_FOUND` | 核对输入、模板、实例、父目录路径；不存在时报告具体路径，不凭空替换为旧项目。 |
| `PERMISSION_DENIED` | 停止并报告权限限制，不提权或更改权限绕过。 |
| `INVALID_DATA` | 不发布；依据用户口述修复 JSON、类型、重复 ID 或规模，保留旧内容。 |
| `INVALID_INSTANCE` | 停止；重新确认当前实例绑定，不能写任意目录。 |
| `INSTANCE_BUSY` | 有写锁；先核实写入者和实例归属，等待已知操作结束；不自动删除锁或终止进程。 |
| `STALE_SNAPSHOT` | 重新 inspect，按新快照合并本轮内容后用新哈希提交；不盲目重试覆盖。 |
| `PORT_IN_USE` | 换一个明确端口重新启动本实例；不关闭未知服务；先 health 确认避免打开旧页面。 |
| `TEST_FAILED` | 查看 msg 和测试断言；修复技能后重新完整运行，不把测试失败宣称成功。 |
| `UNEXPECTED_ERROR` | 停止并展示 msg，定位原因后再做限定修复；不无限重试。 |
| 其他原生 I/O 错误码 | 展示原码和 msg，按文件系统原因处理；不得转为伪成功。 |

端口冲突属于启动失败：stdout 最终为 `PORT_IN_USE`、退出 1，并关闭本次 watcher。运行中磁盘快照无效时 stderr 输出结构化错误，服务保留已验证快照；不是服务退出。SIGINT/SIGTERM 正常停服关闭 watcher、SSE 客户端、HTTP 和定时器；强杀/系统崩溃不保证最终 JSON。

浏览器或自动化工具不可用时，报告未完成真实页面交互验证。浏览器验证是可选环节，不自动安装 CLI，不改用 HTTP 检查冒充交互测试。

原生错误与参数解析错误只输出稳定错误码和中性说明，不回显底层绝对路径、堆栈或用户参数。根据调用时已有的参数定位问题；本地 CLI 成功结果保留明确请求的导航路径，HTTP 不提供这些路径。
