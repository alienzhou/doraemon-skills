# 从观众诉求确定封面

先回答三件事：谁在看、正在遇到什么情况、希望获得什么结果。把这三件事压缩成观众能直接理解的标题，再用简短副标题说明视频如何回应。避免让作者自己的分析术语承担全部吸引力。

## 识别文案问题

- 场景含糊：一句“AI 写代码”可能适用于工作、教程或面试。需要时把“AI Coding 面试”保留在明显位置。
- 收益含糊：“加分”“认可”可能需要观众自己补足；结合上下文可以改成“面试怎么拿高分”等更明确的结果表达。
- 太书面：“提升评价、展现主动性、实践深度”是内容分析，主标题可换成观众日常用语，细节在简介或正文说明。
- 结果与内容脱节：吸引力可以来自目标或问题，但不能把方法分享写成录用保证，不能虚构数据或荣誉。

## 本用户认可案例：AI Coding 面试

原片面向候选人，讲如何在做题过程中展示运行验证、主动判断和实践积累，让面试官看到真实水平。

- “面试官看什么？”：问题泛，候选人能得到什么不够明确。
- “AI 写代码，你怎么加分？”：用户认为容易被当成普通面试题，需要更清楚的场景和结果。
- 用户认可的排文：**AI CODING / 面试怎么 / 拿高分？**
- 副标题：**让面试官看到你的真本事**。
- 视觉：真实视频中的讲述者、深绿背景、米白与金色、大字和少量元素。用户对真人方案的反馈优于该项目的 Memoji 版。

## 迭代与比例扩展

文字或视觉仍有分歧时，先改一张主版。根据用户反馈定位是场景、利益点、语言还是布局问题，不要每次只更换人物素材或批量重做五张。

方向已认可时，直接延续已有授权完成所需比例。扩展时保持同一人物身份、神态、文案和配色，分别重排，检查标题与完整面部。对生成图的安全区要求要在实际图片中检查，必要时微调人物大小或位置。

发布标题与封面互相补充，必要关键词可以重复。多平台文案依平台语气略作调整，具体方法和作者经历保持一致。
