# 小红书内容解析（xhs-intake）

## 核心原则

**先判模态，再选路径，不要默认只听音频。**

上一次踩过的坑：一条 7 分钟视频只做了 ASR 转录就下结论，事后抽帧发现画面里有独立的结构化图示（层级表、对比图），音频只念了一句概括。**画面承载的信息被整段丢掉了。** 所以本 skill 强制先跑判定，再决定读什么。

另一条原则：**证据落盘**。所有素材（视频、音轨、帧、原图、转录）都留在 `out_dir`，结论必须能指回具体的帧号或转录时间戳。

## 模态分类表

| 类别 | 特征 | 解析路径 |
|---|---|---|
| **1a** 音画双载 | 有人声，画面也有独立信息（图示/代码/数据） | transcript + **逐帧读图**，两边交叉引用 |
| **1b** 口播为主 | 有人声，画面基本静止（真人口播、固定背景） | transcript 为主，抽查 2–3 帧确认没有字幕外信息 |
| **1c** 纯画面 | 几乎无人声（BGM / 无旁白演示） | **逐帧读图**为主，transcript 仅补充 |
| **2a** 纯图 | 图片是照片/插画，正文在 `desc` | `desc` + 读图描述视觉 |
| **2b** 图文混排 | 图里有文字但 `desc` 也有完整正文 | `desc` 为主 + 读图补图内独有信息 |
| **2c** 图即正文 | `desc` 只有标签，正文全渲染进图里 | **必须逐图读图**，否则等于没解析 |

判定不靠猜，靠脚本给的指标（见下）。

## 执行流程

脚本在与本 SKILL.md 同级的 `scripts/` 目录下。下文的 `<skill_dir>` 指你加载到的 skill 目录（包含本 SKILL.md 的目录，在技能 catalog / skill_content 的 directory 里给出），运行时直接代入实际路径即可，装在全局或项目级都同样适用。

素材统一落在 `/tmp/xhs/<短名>/`（临时区，不污染当前仓库）。若用户要求归档，再由 `trends-intake` / `note-intake` 决定拷进哪个仓库。

### Step 1 — 抓取（必做）

```bash
python3 <skill_dir>/scripts/xhs_fetch.py "<链接或整段分享文本>" -o /tmp/xhs/<短名>
```

脚本会自己从分享文本里正则出 URL，短链自动跟 302。输出：

- `manifest.json` — 标题、作者、发布时间、IP、标签、互动数、资产清单
- `content.md` — 标题 + `desc` 正文
- `page.html` — 原始 SSR 页面（排查用）
- 视频：`video.mp4`（自动选最高码率）+ `audio.wav`（16k 单声道）
- 图文：`imgs/00.jpg …`（原图，非缩略图）

`modality` 字段直接给出 `video` / `image_text`。

### Step 2 — 分模态判定子类

**视频**：

```bash
python3 <skill_dir>/scripts/xhs_analyze_video.py /tmp/xhs/<短名> --fps-interval 20
```

产出 `transcript.txt`（带时间戳）、`transcript.plain`、`frames/NNN_SSSSSs.jpg`（文件名带秒数，便于和转录对齐）、`keyframes/`，以及 `analyze.json` 里的判定：

- `speech_chars_per_sec` < 0.5 → **1c**
- `visual_variance` < 3.0 → **1b**
- 否则 → **1a**

`subtype_hint` 字段直接写了该读什么。**照它做，别自作主张跳过读图。**

**图文**：看 `manifest.json`：

- `desc_len` < 50 且有多张图 → **2c**，逐图 Read
- `desc` 完整成段 + 图是照片 → **2a/2b**

### Step 3 — 拼联系表（视频 1a / 1c 必做）

把抽帧拼成一张带时间戳的大图，实现「图文一起看」：

```bash
python3 <skill_dir>/scripts/xhs_contact_sheet.py /tmp/xhs/<短名> --cols 4 --cell-w 720
```

产出 `sheet.jpg`（或多页 `sheet_p1.jpg`…）+ `sheet.json` 索引。每格左上角有 `#序号 mm:ss` 角标：序号用于回指某格，秒数用于和 transcript 对齐。

**分辨率红线（实测）：单格宽度 ≥ 700px。**

| 配置 | 结果 |
|---|---|
| 3×3 @ w960 | 小号注释都清晰 |
| 3×3 @ w640 | 主标题可读，**小注释已糊** |
| 4 列 21 帧 @ w720 | 主标题 + 二级要点可读，最小号注释糊 |

低于 700px 时主标题仍能读，但最小号注释会丢——而那些注释往往正是画面独有的信息（如层级图里的 `O(n) 贵 / O(1) 便宜`）。脚本会对过小的配置打 warning。

### Step 4 — 读取：先总览，再钻取

**两级策略，缺一不可：**

1. **总览**：`Read` 联系表大图，一次看完整条叙事结构，判断哪些格子承载了音频没有的信息。
2. **钻取**：对上一步标记的格子，**回读 `frames/` 下的单帧原图**。

⚠️ **不要只看总览图就下结论。** 总览负责「不漏结构」，单帧负责「不丢细节」。实测中总览图上糊掉的小字里藏着关键信息（实验方法的具体手段、日志的真实条目格式）。

图文笔记同理：`imgs/` 下逐图 `Read`，2c 类一张都不能跳。

转录里的错别字很常见（人名、术语、英文），结合上下文纠正后再引用，例如「宗述→综述」。产品代号可能被听成多种写法（如 `C-16` / `C10` / `Cteno` / `Citano`），**以画面里出现的书面拼写为准**——这是联系表的另一个价值。

### Step 5 — 输出

给用户的解析结果包含：

1. **元信息**：标题、作者、发布时间、互动数、标签
2. **模态与所用方案**：明确说清是听了音频、读了图、还是两者
3. **内容提炼**：按原文脉络展开，不要过度抽象
4. **证据锚点**：关键结论标注来源（`transcript 06:54` / `#09 帧` / `imgs/02.jpg`）
5. **信息缺口**：诚实说明拿不到的部分（如评论区）

## 已知限制

- **签名时效**：视频直链带 `sign` + `t`，**必须现取现下**，隔天失效。图片链接同理。
- **评论区**：SSR 首屏不含评论（`comments.list` 为空），`manifest.json` 会标注 `comments_note`。需要评论时得走浏览器渲染（myflicker-browser skill）滚动加载，或让用户直接截图。
- **私密/登录笔记**：拿不到直链，脚本会报错退出。
- **只读公开数据**：不做登录态爬取，不并发轰炸，一条一条来。
- **页面结构可能变**：`xhs_fetch.py` 有双重兜底（`__INITIAL_STATE__` 解析失败时回退正则捞 `masterUrl`）。若都失败，先看 `page.html` 确认是不是被风控页替换了。

## 依赖

| 用途 | 工具 | 缺失时 |
|---|---|---|
| 抽音轨 / 抽帧 | `ffmpeg` `ffprobe` | 必需，`brew install ffmpeg` |
| ASR | `mlx_whisper`（Apple 芯片首选） | 回退 `whisper`；都没有则跳过转录并告警 |
| 画面变化度 / 联系表 | `PIL` (Pillow) | 缺失则无法拼联系表，`visual_variance` 为 null，判定退化为只看语音密度 |

ASR 全本机运行，不走网络、不消耗 API 额度。7 分钟视频约 1 分钟出全文。

## 与其他 skill 的边界

- 解析完想**收录进仓库** → 交给 `trends-intake`（外部资讯）或 `note-intake`（做成笔记）；这两个是项目级 skill，只在对应仓库里存在。本 skill 只负责解析，**不擅自写入任何仓库**。
- 解析完想**继续讨论** → 直接接 `thinking-partner` / `discuss-for-specs`，把解析结果当讨论素材。这是本 skill 最常见的下游。
- 想**做小红书内容** → `xhs-creator` / `xhs-cover-designer`，与本 skill 无关。
- 素材是**非小红书的演示视频/发布会** → 用 `media-teardown`，那套更重（要出 PRD + 技术方案）。
