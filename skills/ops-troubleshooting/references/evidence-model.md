# 证据模型

## 证据层级

排障证据不只包括应用日志：

1. 用户可观察现象与可重复步骤。
2. 结构化应用日志和运行轨迹。
3. 指标、Trace、消息帧与诊断端点。
4. 进程、线程、文件、网络和操作系统状态。
5. 对端服务日志和第三方响应。
6. 代码、配置、协议与部署事实。

代码能证明“某版本按设计会怎么执行”，不能单独证明生产现场确实走过该路径。运行日志能证明“观测到了什么”，但未埋点处没有日志不能证明未执行。

## 结论级别

### 确诊

满足：

- 现象与因果机制能够连成闭环。
- 断点前后都有证据。
- 主要竞争假设已被反证或不可能同时解释证据。
- 结论可由其他人复查。

### 最可能

满足：

- 多条证据一致指向某机制。
- 仍存在当前观测无法区分的合理解释。
- 已明确缺少哪条证据。

### 未知

满足任一情况：

- 证据互相冲突。
- 时间窗、版本或环境无法确认。
- 关键链路没有任何观测。
- 只能根据代码猜测现场行为。

## 常见误判

- 把最早出现的 error 当成根因。
- 把时间上相邻当成因果关系。
- 搜不到日志就判断代码没执行。
- 只读调用方，不查对端是否受理。
- 只看日志，不读代码中的预期控制流。
- 从当前代码推断旧版本现场。
- 忽略时区、时钟漂移、重试和重复上报。
