# Ops Diagnostic

当现有证据只能支持“疑似”时，不继续猜测，而是设计下一轮能拉开竞争假设的证据。

## 职责边界

本 Skill 解决的是观测不足，不是直接修复故障。它可以接续一次排障，也可以在用户只提供现象和怀疑时独立使用。

核心循环：

```text
竞争假设
→ 证伪与确诊条件
→ 判别性埋点
→ 预期事件序列
→ 干净复现
→ 证伪、确诊或迭代
→ 决定埋点去留
```

## 四条硬约束

1. **只增加观测，不改变业务语义。** 不主动改变分支、状态、返回值、重试、异常处理或调用顺序。任何埋点都会产生一定运行开销，尤其可能扰动竞争条件和偶发故障；设计时应最小化字段计算与 I/O，并显式记录采样、缓冲、日志级别和潜在 Heisenbug 风险。若必须改变行为才能验证，那是另一项实验，需要单独授权。
2. **每条埋点对应明确假设。** 禁止“多撒一些日志再看看”。
3. **字段必须具有判别力。** 记录状态、差异、计数、存在性、阶段耗时或终态来源，而不只是“执行到这里”。
4. **收尾必须决定去留。** 有长期价值的埋点转为正式观测资产；只服务本次实验的日志和辅助状态应回滚。

## 工作流程

### S1. 收集当前证据与未知项

明确：

- 已确认的事实。
- 当前疑似机制。
- 哪些日志或运行时证据已经检查过。
- 哪个断点之后无法继续判断。
- 是否存在安全、隐私、性能或复现环境限制。

不要重复 `ops-troubleshooting` 已经完成的取证。

### S2. 列出竞争假设

假设应描述可发生的机制，而不是宽泛模块名。例如，“取消信号到达 worker 后未传给当前任务”比“worker 有问题”更可验证。

互斥与可叠加的假设都应列出。给每条假设编号 `H1..Hn`。

### S3. 定义证伪与确诊条件

对每条假设回答：

- 出现什么观测意味着它成立？
- 出现什么观测意味着它不成立？
- 当前日志能否给出该观测？

如果现有证据已经足够，停止加日志并直接判定。只有缺失必要观测时才进入下一步。

### S4. 设计最小判别性埋点

优先选择能同时区分多条假设的少量事件。常用判别量：

- 状态 flag 和状态前后值。
- 两个事件之间的相对时间。
- 进入、退出和终态来源。
- 队列长度、处理数量和重试次数。
- 某信号、资源或记录是否存在。
- 结果由哪个分支或组件产生。

需要跨调用观察诊断状态时，可增加仅供日志读取的临时私有字段；这些字段不得参与任何业务判断。

实现前读取仓库现有日志规范。若没有规范，采用最小基线：复用项目已有 logger；事件名稳定且低基数；变量放结构化字段；高频诊断使用受控 debug 级别或采样；不记录凭据、用户内容和完整对象。`ops-logging` 可提供更完整指导，但本 Skill 不依赖它。

### S5. 预写预期事件序列

在复现前写清每条假设命中和未命中时日志应该是什么顺序。使用 [references/hypothesis-ledger.md](./references/hypothesis-ledger.md) 的假设账，避免看到结果后倒推故事。

### S6. 检查改动纯度

逐项审查 diff：

- 是否改变控制流、状态或调用顺序。
- 是否新增 `await`、重试、异常吞噬、返回或 abort。
- 临时字段是否只被写入和记录。
- 是否记录了凭据、用户内容或其他敏感数据。
- 字段计算、格式化、锁和 I/O 是否可能扰动被观测行为；必要时改用惰性字段、采样、缓冲或更低日志级别，并在假设账记录剩余扰动风险。
- 是否已记录临时改动清单和可恢复的代码版本，避免复现中断后遗留诊断代码。

运行项目要求的 lint、typecheck 和相关测试。

### S7. 干净复现并判定

复现前约定尝试次数、观察窗口、日志容量和停止条件。隔离上一次运行、并发任务、休眠、重连或缓存等噪声。记录复现步骤、版本、时间窗和关联 ID，然后按预写账本逐条判定：

- `confirmed`：命中确诊条件。
- `refuted`：命中证伪条件。
- `insufficient`：观测仍不足。
- `contradictory`：证据互相冲突，需要修正假设。

全未命中也是新信息，应回到 S1，而不是从旧数据中硬选一个根因。达到停止条件仍未复现时，结论保持 `insufficient`：保留最小、受控且有自动过期或明确清理方式的观测网，或回滚本轮改动；不要无限循环复现。

### S8. 收尾与回流

逐条决定新增观测的归宿：

- **永久保留**：关键状态迁移、终态归因、跨边界结果或长期有价值的阶段耗时。按仓库规范重命名、调整级别，并同步日志文档或事件词典。
- **临时回滚**：高噪声计数、一次性怀疑点、仅服务当前实验的辅助字段。部署或复现中断时也按临时改动清单恢复，不把未决诊断代码留在系统中。

长期等待偶发复现时，只保留经过安全、性能和隐私评估的最小观测，并约定 owner、观察窗口与清理条件。

若本轮来自一次排障，把假设账、复现条件和关键证据交回排障报告，将“疑似”更新为与证据相符的结论。

## 输出

提供：

1. 当前证据缺口。
2. 竞争假设账。
3. 最小埋点方案和代码改动。
4. 复现前预期事件序列。
5. 复现后的逐条判定。
6. 埋点去留清单。
