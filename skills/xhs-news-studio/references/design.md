# 设计与封面

## 一、选择自由度

**参考执行**的目标是降低设计决策量：看案例图，保留间距、字级比例、卡片节奏，替换内容与主题视觉；不要原封不动带走旧标题、旧日期、数字、金丝雀、来源或账号。默认从自带 starter 的 `editorial` 主题开始。

**自由设计**的目标是为题材建立新的视觉方向：可以改为杂志排版、干净科技白、深色产品发布、纸张拼贴等；可以完全重构 CSS/组件。先在 `brief.md` 用两句话写明色彩、字体、主视觉及其与题材的关系，然后制作一张封面和一张信息最密的内页，能读清再扩展全套。不要为了显得创新随意加渐变、玻璃卡片和发光线条。

不要仅依据模型自报“我很强”决定。用户要求、现成参考、工具可用性、首轮视觉检查表现才是选择依据。第一次审图失败时先改排版；两次仍失控就用案例结构完成，不无限尝试新风格。

## 二、参考库

当前成熟案例：[Pixel Canary](pixel-canary.md)。该用户认可的成果同时覆盖大字封面、用途介绍、通过率比较、社区结果和身份线索。它是参考，不是品牌规范。

多主题发布会合集另参考 [DevDay 视觉版](devday-visual-18.md)：用户认可了官方画面、数据比较与语义图交替的阅读节奏，以及含封面的页数控制。借用信息取舍与布局关系，不照搬事件日期、亮点数量、素材占比或逐页内容。

starter 另提供 `light` 和 `night` 色彩变体。它们只是起始方向，**未经用户认可，不称为经典案例**。可以把用户未来认可的其它作品加入案例库；每次仅读与当前题材有关的案例，不全量加载所有图片。

参考优先级：用户给的作品/品牌 → 已认可案例 → starter → 自由设计。参考分析说明具体借用的关系，例如“标题占上方四分之一、数字并排、来源弱化”，不要照搬无关图案。

## 三、封面层级

一个封面通常只承载三层文字：

1. **新闻提示**：如“新模型上线”“开放体验”“正式发布”。视觉上可用高对比标签，不要只有角落的小字让人猜新闻性。
2. **主体名称**：在信息流缩略图里仍清楚，通常是最大的字；英文长名先调整字距/换行，不用缩成角标。
3. **点击看点**：有证据的数字、实际用途或能在内页回答的问题。例如“超过 GPT-6？”；不把未知结论写成断言。

名称 + 新消息至少要有一个强文字块。看点应让人知道进来能得到什么，不让观众误以为有资料未支持的结果。出身未知可以做副线，不必每次用“谁家的”。

保留一个主视觉焦点；“概念插画 / 非官方标识”小字与实测作品分清。缩略图只读标题和看点就足够，页脚无需在缩略图中成为主角。

### Pixel 案例中的尺寸参考（1080×1440）

- 安全边距约 60–72px；主标题 110–146px；新闻标签 36–44px；钩子 60–72px。
- 内页标题 64–76px、正文约 28–34px、来源约 20–23px。
- 上方容纳标题，主体视觉放中下部；这次金丝雀头部从约 y=440 开始，所以文字要在此前结束。

这些是参考尺寸，不是全局硬限制。长中文标题、不同字体和其它比例应重排。避免逐页覆盖几十条 CSS 补丁；稳定后整理为作用域清楚的样式。

## 四、图表与排版

一页一结论、一块主视觉/图表。统计比较优先条形图；任务通过数可用总数格子；时间线写发布节点；身份线索用证据对照。不要用插画伪装效果截图。

先为每页选一个能解释内容的视觉，再组织文字。多主题合集允许同页有两个相关亮点，但要让读者看出它们的关系。适合的主视觉包括：产品界面展示“做出了什么”、对比图展示价格/效果变化、流程图展示操作、边界图展示隐私/权限、时间线展示开放顺序。无数据时用能力示意，标明“示意”；箭头只表达资料支持的步骤或依赖，不把独立 API 画成必经链路。

整套需要阅读节奏：保持字体、色彩和来源样式一致，按内容交替使用大画面、数字对比、语义图、简短说明等布局。只换背景色、图标或卡片数量仍可能是同一种文字模板。先看全套缩略图，连续几页都在读相似长框时，合并重复文字或换成能回答问题的画面；不要为变化强行添加无意义装饰。无需每页都有照片，也无需凑齐固定数量的版式。

正文建议每页约 80–160 汉字作为初稿预算，数据标签和来源另计；不把字数预算变成机械卡点。短句、适度留白、每一层最多一到两种字重。来源能读，但弱于结论。

颜色表达语义需明确：黄色是关注重点，不自动等于高分；绿色/红色不要无说明地映射成优劣。条形图显示单位、方向、时间和比较范围。相同比例画等长条。

## 五、图像生成与真实证据

产品发布与效果报道先检查是否有相关的官方宣传图、产品演示、官方文档截图或可核对的作者作品，再决定是否需要生图。官方图应来自本次范围或当前相关产品，能解释具体功能；旧活动图、无关品牌图不能充当这次效果证据。合理使用一部分真实画面，数量按信息价值决定，不固定官方图占比。

- 先看原图，再选裁切和显示尺寸；界面中的关键区域应能在导出 PNG 上辨认，不把完整桌面缩成无人能读的小图。必要时使用局部特写，并标“局部”；完整原图和出处留在源文件中。
- 图注区分“官方宣传图”“官方产品演示”“作者实测”“能力示意”。官方演示不写成自己实测；示意图不伪装官方截图。来源放短图注或页脚，完整图源另存，避免每张图注重复长篇背景。
- 使用当前工具能够正常访问的素材与已授权的用户素材；访问受限时换可核对素材或示意，不绕过限制。视觉辅助不能替代正文中的版本、状态和条件。

- 生图用于主题视觉、背景和示意；精确标题、数据、来源留给 HTML。
- 提示词写画幅、主体位置、留白区域、色彩、材质、光线，明确不要字、Logo、水印。真实结果截图不能用生图“美化”后冒充原效果。
- 透明配图需要真正 alpha，棋盘背景不算透明。用图像属性检查通道，再目视边缘。
- 素材夹带字、鸟压到标题、暗图导致字看不清，均要修正后再渲染。
- 没有生图工具：使用干净的排版和矢量概念图；不能为了工具缺失退回只交方案。

可改写的生成提示词范例：

> 3:4 editorial concept illustration of [主题意象], [材质和配色], main object in lower two-thirds, dark clean negative space in upper 30% for later typography, restrained lighting, no text, no letters, no logo, no watermark. Concept art, not a screenshot of a real product.

这个范例只描述构图，不固定所有作品都用深色、像素或鸟。
