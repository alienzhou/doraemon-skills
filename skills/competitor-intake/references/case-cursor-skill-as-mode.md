# 已验证案例：Cursor「Skill as Mode」

首次跑通本 skill 全流程的样本。遇到拿不准的地方，对照这个案例看每一步实际是怎么走的。

> 案例中的产出链接（文档 URL、任务号）属于内部环境，此处不列。关注的是**各步骤的判断过程**。

## 采集

firecrawl 抓 Cursor 官方 changelog，锁定一条：

> 将任意技能用作自定义模式：输入 `/` 后，选择一项技能并按 ⌥⏎（Mac）或 Alt+Enter（Windows），或者选择「用作模式」。

## 选题（关键，示范粒度判据）

该次 changelog 有四个功能候选：**订阅体系改版 / 自定义模式 / 子 Agent 独立 VM / `/goal` 目标驱动**。

只有「自定义模式」三道闸全过：

- 一句话说清：Skill 从「用一次」变成「一直用」。✅
- 一个交互点验完：`/` 菜单里按 `⌥⏎`。✅
- 一期能独立上线：不依赖后端、不依赖调度。✅

其余三个都涉及云端环境、调度或长期状态机，属于大模块，全部淘汰。

**这一步是整个 skill 的价值所在**：四选一，淘汰掉的三个单独看都很诱人，但都会让后面的取证和文档围着说不清的大模块空转。

## 取证

三步三图，每步都区域截图 + `sips` 裁剪：

1. 初始态 —— 输入框工具栏无任何模式徽标
2. 输入 `/<skill名>` —— **高亮项**右侧出现 `⌥⏎ to Use as Mode`（非高亮项不显示，是个很克制的设计）
3. 按 `⌥⏎` —— 菜单关闭、输入框正文清空、工具栏出现 `⚡ <skill名> ×`

辅助功能树第二路证据：徽标由 `AXStaticText value="<skill名>"` + `description="Remove <skill名>"` 的 `AXButton` 组成，确认 `×` 是标准一键退出。

**踩到的坑**（全部已收进 `capture-pitfalls.md`）：

- AX 树懒加载，要先 typeText 才建树；
- Cursor 在外接屏负坐标区，全屏截图连抓错两次；
- 另一个应用抢占前台，导致区域截图抓错窗口；
- 首次截图时输入框有上一轮遗留的徽标和一个通知横幅（界面残留污染）。

还原现场：`cu act press @eNNN --expect '{"until":"absent","text":"<skill名>"}'` → `worked / verified`。

## 文档

七段结构，三张裁剪图内联，另加「附：调研方法说明」。

方案相对竞品做了一处**收紧**：同一时刻只允许一个模式，再设一个即替换——避免多 Skill 指令冲突，也避免徽标区被撑爆。

> 这类「我们和竞品不一样的地方」要显式写出来并给理由，否则评审时会被当成漏抄。
